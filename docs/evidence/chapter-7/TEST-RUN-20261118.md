## Local Supabase run — 18 November 2026

The local run used a production-mode Next.js server on `127.0.0.1:4410`, Chrome, and the local Supabase API at `127.0.0.1:57321`. The test process asserted that exact loopback endpoint before starting. `.env.local` was not changed, and no hosted Supabase endpoint was used for this run. The app was built earlier with `pnpm exec next build --webpack`; that build succeeded.

### Results

- Unit tests: **37 passed** (`pnpm test:unit`; 10 files).
- Playwright: **12 passed, 2 failed, 1 skipped** (15 tests, one worker).
- Passing browser coverage included storefront rendering, add-to-cart and cart opening, 375 × 812 dark-mode layout, staff and customer route guards, invalid-login feedback, customer registration fields, password recovery forms, service-worker headers and offline shell behavior, plus the Phase 3 customer/POS/receipt/stock/concurrency workflow.
- Phase 1C initially reached the customer dashboard but failed because its old assertion expected `Hello, <full name>`; the current page displays `Good to see you, <first name>.` The assertion now matches the current dashboard, and a focused rerun passed the complete staff/customer identity and isolation workflow in 47 seconds. A preceding rerun had timed out while local Auth/REST were unavailable.
- Phase 2 product/category creation, edit and search passed in the full run. The damage movement check failed: expected stock `11.000`, observed `11.250`; the inventory form displayed “Opening stock is already recorded. Use a stock adjustment to correct it.” Fixture cleanup reported success. A focused rerun later stopped at the staff sign-in form, which remained pending when the local Auth/REST endpoints became unreachable; it did not reach inventory.
- Phase 1D confirmation email flow was skipped. Local Auth is configured to auto-confirm accounts, so this run did not test a confirmation link through Mailpit.
- The Phase 3 local E2E passed, including POS cash and externally confirmed Mobile Money receipts, customer handling, stock reconciliation and concurrency. Its append-only QA sale and movement rows remain in the local database. This was not a Paystack checkout or email-delivery test.
- No database reset or migration was applied. Local migration history is not fully aligned with the repository. The local Auth/REST endpoints became unreachable during the extended reruns (they were restarted once without a reset), and were unreachable at the final health check. Database-sensitive failures should be rerun after the local stack is stable and its migrations are reconciled.

The detailed Playwright traces and raw screenshots are in `local-supabase-artifacts-20261118-run2/`. The isolated Phase 1C timeout artifacts are in `local-supabase-phase1c-rerun-20261118/`. Curated figure images are in `screenshots/`.
